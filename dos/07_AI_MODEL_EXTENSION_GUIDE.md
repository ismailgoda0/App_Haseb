# 07 — دليل نماذج الذكاء الاصطناعي والمطورين للتطوير المستقبلي (AI Model Extension Guide)

> **موجّه إلى:** أي نموذج ذكاء اصطناعي (AI Assistant / LLM) أو مهندس برمجيات يعمل على صيانة هذا المشروع أو توسيع إمكانياته.

تم بناء مشروع **HomeCash** بتصميم معياري صارم (Modular Clean Architecture) يتيح لك إضافة أي ميزات متقدمة أو توسيع قدرات الذكاء الاصطناعي دون المساس بالبنية الأساسية المستقرة.

---

## 1. كيفية إضافة محفظة جديدة أو بنك جديد

إذا أصدر بنك مصري أو مزود دفع جديد خدمة جديدة (مثال: محفظة جديدة من بنك القاهرة أو بنك الإسكندرية):

1. **الخطوة الأولى:** افتح ملف `AntiFraudValidator.kt` وأضف اسم المرسل الرسمي إلى قائمة `LEGITIMATE_SENDERS`.
2. **الخطوة الثانية:** افتح ملف `SmsParserEngine.kt` وأضف دالة استخراج مخصصة:
   ```kotlin
   private fun parseNewWallet(sender: String, text: String, raw: String): ParsedSmsResult? {
       // استخراج المبلغ، الرصيد، كود العملية، ورقم الطرف الآخر
   }
   ```
3. **الخطوة الثالثة:** استدع الدالة في دالة `parse(...)` الرئيسية قبل المعالج العام `parseGeneric`.

---

## 2. دمج نماذج الذكاء الاصطناعي (On-Device AI / LLM)

يمكن تعزيز ذكاء التطبيق بعدة طرق:
1. **تصنيف المعاملات الذكي عبر Gemini Nano أو ONNX Runtime:**
   - يمكن إضافة واجهة `AiClassifier` تحلل نص الرسالة وسياق المعاملة لتحديد الغرض منها (مثال: دفع إيجار، مشتريات بضاعة، مصاريف شخصية).
2. **المساعد الصوتي المالي (Financial Chat Assistant):**
   - يمكن ربط التطبيق بواجهة محادثة ذكية تستعلم من قاعدة بيانات Room للإجابة عن أسئلة التاجر الطبيعية، مثل:
     - *"كم إجمالي ما استلمناه على فودافون كاش اليوم؟"*
     - *"من هو العميل الأكثر تحويلاً هذا الأسبوع؟"*
     - *"هل يوجد أي فارق معلق في حسابات الكاشير 2؟"*

---

## 3. التكامل مع طابعات الفواتير الحرارية البلوتوث (POS Printer)

لإتاحة طباعة إيصال ورقي فوري للعميل:
- كائن `TransactionEntity` يحتوي بالفعل على كافة الحقول المطلوبة للإيصال (`operationCode`, `amount`, `cashierCommission`, `occurredAt`, `counterpartyNumber`).
- يمكن إضافة فئة مساعدة `BluetoothReceiptPrinter` لإرسال أوامر ESC/POS وطباعة إيصال رسمي باسم المحل.

---

## 4. نصائح هامة لصيانة الكود
- حافظ دائماً على تدفق `Unidirectional Data Flow` (تعديل الحالة من خلال ViewModel فقط).
- لا تقم بتعديل النص الأصلي للرسالة `rawText` في أي استعلام؛ النص الأصلي هو الحجة القانونية والتدقيقية للتاجر.
- أي إضافة لقواعد البيانات يجب أن تتم عبر إضافة هجرة جديدة (Migration) أو الحفاظ على `fallbackToDestructiveMigration` في بيئة التطوير فقط.
